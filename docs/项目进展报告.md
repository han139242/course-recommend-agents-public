## 二、研究背景与目标

### 2.1 研究背景

当前高校人工智能专业课程体系存在显著的"知识孤岛"现象——《机器学习》《深度学习》《自然语言处理》《计算机视觉》等课程各自为政，学生在学习过程中难以建立**跨课程的知识关联网络**。例如，学生在《深度学习》课程中学习"自注意力机制（Self-Attention）"时，往往无法直观感知该知识点与《线性代数》中"矩阵运算与特征分解"、《概率与统计》中"Softmax 概率归一化"、以及《自然语言处理》中"序列到序列建模"之间的深层依赖关系。

已有研究表明，知识图谱（Knowledge Graph）能够有效表征实体间的语义关系，在智能教育领域已有 KnowEdu、MOOCCube 等知识图谱构建工作。然而，这些工作多聚焦于**单一课程内部**的知识点组织，缺乏对**跨课程知识关联**的系统建模与个性化推荐能力。

### 2.2 研究目标

本项目旨在构建一套**突破课程边界的知识点推荐智能体系统**，核心目标包括：

1. **跨课程知识图谱构建**：基于 LLM（大语言模型）驱动的知识抽取管线，从 15 门 AI 相关课程的教材文本中自动抽取结构化知识点，并以 6 种语义关系建模跨课程知识关联，存储于 Neo4j 图数据库
2. **AI 推荐智能体**：基于学生学习进度、掌握度画像与图谱拓扑结构，由大语言模型（DeepSeek）驱动的智能体实时生成个性化学习路径推荐
3. **交互式知识图谱浏览器**：自研 Canvas 2D 高性能渲染引擎 + D3-Force 物理仿真布局，实现 Neo4j 风格的逐层展开探索，支持千级节点 60fps 流畅交互
4. **学习分析仪表盘**：多维度能力画像、学习热力图、遗忘曲线跟踪，为学生提供全方位学习状态感知

**（3）自研高性能 Canvas 2D 图谱渲染引擎**

这是本项目的**核心技术创新**之一。放弃传统 DOM/SVG 图谱库（如 ECharts、AntV G6），完全自主研发基于 **Canvas 2D + D3-Force** 的渲染引擎，从底层解决大规模知识图谱的交互性能瓶颈。

渲染引擎由 6 个核心模块组成：

| 模块 | 文件 | 职责 | 关键技术 |
|------|------|------|---------|
| 物理仿真引擎 | `useGraphEngine.js` | D3-Force 力导向布局 | 多体引力（Many-Body）、碰撞检测、展开锚定力、布局冻结/解冻 |
| 渲染管线 | `useGraphRenderer.js` | Canvas 2D 帧绘制 | `requestAnimationFrame` 渲染循环、脏标记优化、分层绘制 |
| 交互控制器 | `useGraphInteraction.js` | 用户手势处理 | 平滑缩放/平移动画（Tween）、惯性拖拽、命中检测委托 |
| 绘制器 | `graphDraw.js` | 节点/边视觉绘制 | 星云背景光晕、径向渐变填充、标签自动换行、外发光效果 |
| 布局器 | `graphLayout.js` | 智能空间布局 | 环形展开布局、碰撞避让、视口约束、扩展锚定偏置 |
| 数据转换器 | `graphTransform.js` | 图数据预处理 | 节点样式计算、课程颜色映射、学习状态驱动渲染 |

**核心性能指标**：

| 指标 | 达成值 |
|------|-------|
| 节点承载量 | 千级节点，60fps 流畅渲染 |
| 展开/收起动画延迟 | < 200ms |
| 首屏渲染时间 | < 500ms（14 个种子节点） |
| 缩放范围 | 0.4x — 2.0x 连续缩放 |

**（4）AI 推荐智能体集成**

基于 DeepSeek 大语言模型构建了多角色推荐智能体，通过 **Server-Sent Events（SSE）** 实现流式对话输出：

- **对话式交互**：学生用自然语言向 AI 助手提问（"帮我解释注意力机制"、"我下一步该学什么"）
- **上下文感知推荐**：AI 结合当前选中知识点、学生掌握度画像、前置知识链，自动生成个性化推荐
- **图谱控制指令**：AI 回答可直接操控图谱界面——聚焦节点、展开子图、高亮前置链路、筛选课程
- **多模式无缝切换**：在线模式（DeepSeek API）→ 本地兜底模式（网络异常时自动降级）→ 页面执行模式（结构化指令下发到前端）

AI 智能体支持的图谱操控指令：

| `open_knowledge_detail` | 跳转到知识点详情页 |
| `filter_course` | 按课程筛选图谱显示 |
| `fit_graph_view` | 自动适配视图到全部可见节点 |
| `reset_graph_scene` | 重置图谱为初始状态 |

### 4.1 创新点一：突破课程边界的跨课程知识图谱

**创新性阐述**：

传统教学平台将知识点组织为"课程 → 章节 → 知识点"的**树状层次结构**，本质上是"信息组织"而非"知识建模"。这种结构无法表达跨课程知识关联——学生看到的是一棵棵孤立的"课程树"，而非一张互相连通的"知识网络"。

本项目首次针对 AI 专业课程体系进行了**全覆盖的跨课程知识图谱建模**：

1. **覆盖广度**：统一建模 15 门 AI 相关课程，打通数学基础（高等数学、线性代数、概率与统计）→ 核心方法（机器学习、深度学习）→ 应用方向（NLP、CV、强化学习）→ 工程实践（AI 工程、Python 编程）的完整知识链路
2. **语义丰富度**：定义 6 种区分度高的语义关系类型（前置依赖、子主题、组成、相关、使用、应用），相比已有工作（如 MOOCCube 仅用 prerequisite 和 part-of 两种关系）更精细地刻画了知识间的多元联系
3. **自动化构建**：通过 LLM 驱动的知识抽取管线（而非人工标注），实现了从教材文本到结构化图谱的端到端自动化，显著降低了知识图谱构建成本

### 4.2 创新点二：LLM 驱动的多角色推荐智能体

**创新性阐述**：

现有知识推荐系统多采用协同过滤或基于内容的推荐算法，缺乏对学习语境的深度理解。本项目创新性地将大语言模型（LLM）作为推荐智能体的"认知核心"，通过以下机制实现上下文感知的个性化推荐：

1. **知识图谱上下文注入**：将当前选中节点的邻域拓扑结构、前置知识链、所属课程信息序列化为 LLM 可理解的上下文，使推荐具有图谱结构感知能力
2. **学习状态画像融合**：将学生的掌握度分布、答题历史、学习进度注入对话上下文，实现个体化推荐
3. **结构化指令输出**：LLM 不仅生成自然语言回答，还输出结构化的图谱操控指令（JSON 格式），实现"对话即操作"的交互范式——AI 的一次回答可以同时在图谱上聚焦节点、展开子图、高亮学习路径
4. **多模式容错架构**：在线模式（DeepSeek API）→ 本地兜底模式 → 页面执行模式，确保任何网络条件下系统均可用

**与申报书中技术路线的演进说明**：

原申报书中提出采用 BERT/Transformer 进行知识表示学习、强化学习（RL）进行推荐策略优化。在实际研发过程中，考虑到 2025—2026 年大语言模型技术的快速发展，我们决定采用更先进的 **LLM-as-Agent** 范式替代传统的 BERT + RL 方案：

| 原计划方案 | 实际采用方案 | 演进理由 |
|-----------|------------|---------|
| BERT 知识表示学习 | DeepSeek LLM 上下文理解 | LLM 具有更强的语义理解和推理能力，无需针对特定任务微调 |
| 强化学习推荐策略 | LLM + 图谱拓扑混合推荐 | LLM 天然具备多步推理能力，结合图谱结构约束可生成更具解释性的推荐路径 |
| 静态推荐列表 | 流式对话 + 图谱操控指令 | SSE 流式输出提升交互体验，结构化指令实现"对话即操作" |

这一技术演进使系统的推荐能力从"基于统计特征的被动推荐"升级为"基于语义理解的主动对话式推荐"，更符合当前 AI 技术发展趋势。

### 4.3 创新点三：自研 Canvas 2D 高性能图谱渲染引擎

**创新性阐述**：

传统前端图谱可视化方案（ECharts 关系图、AntV G6、D3.js SVG）在大规模知识图谱场景下面临**严重性能瓶颈**——DOM/SVG 节点数超过 500 后帧率急剧下降，无法支撑流畅的交互探索。

本项目完全自主研发了基于 **Canvas 2D API + D3-Force 物理仿真**的渲染引擎，实现以下技术突破：

1. **Canvas 2D 即时渲染**：绕过 DOM 树的开销，直接在 Canvas 上绘制节点、边、标签、光晕等图形元素，渲染性能与节点数量呈线性关系而非指数关系
2. **D3-Force 物理仿真驱动布局**：采用多体引力（Many-Body Force）、碰撞检测（Collision Force）、展开锚定力（Expansion Anchor Force）的组合力模型，实现知识节点的智能空间布局
3. **Neo4j Browser 风格逐层展开**：首屏仅显示 14 个种子节点（每门课程选取核心代表），双击展开子图，子节点以环形布局从中心向外扩散，支持多级嵌套展开
4. **课程星云背景**：每门课程的节点区域自动绘制半透明"星云"光晕（Nebula Background），颜色与课程配色方案一致，帮助学生直观识别知识点的课程归属
