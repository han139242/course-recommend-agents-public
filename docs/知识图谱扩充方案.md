# 任务：为 AI 专业知识图谱补充知识点

你是一个人工智能教育领域的知识图谱构建专家。我正在构建一个"突破课程边界的人工智能专业知识点推荐系统"，使用 Neo4j 存储 20 门课程的知识点和关系。当前图谱已经覆盖基础课程、AI 核心课程、工程治理课程和前沿扩展课程，但仍需持续审计新增知识点是否完整、分类是否正确、关系是否连通。

**你的任务：按照下面的规则，为每门缺失/不足的课程生成完整的知识点 JSON 数据。由于单次输出长度限制，请一次生成一门课程，我会多次让你生成不同课程。**

---

## 一、输出 JSON 格式（严格遵守）

每门课程输出一个独立的 JSON，格式如下：

```json
{
  "source": "course_xxx",
  "course_title": "课程中文名",
  "nodes": [
    {
      "canonical_name": "知识点名称",
      "entity_type": "concept",
      "description": "一句话描述，20-50字"
    }
  ],
  "relations": [
    ["源知识点名称", "目标知识点名称", "SUBTOPIC_OF"]
  ]
}
```

**硬性要求：**
- `source` 和 `course_title` 必须用下面第二节表格中的值，不要自己编
- `relations` 中的名称必须和 `nodes` 中的 `canonical_name` **完全一致**（一个字都不能差）
- 如果引用了其他课程的知识点（如"线性代数"课程引用"机器学习"中的"PCA"），也要写入 `nodes`，导入时会自动去重
- JSON 必须合法：**不要有注释、省略号（...）、尾逗号、截断**
- 如果单次输出放不下，宁可少写几个节点，也**不要输出不完整的 JSON**

## 三、知识点规则

### 3.1 canonical_name 命名

- 使用中文学术通用名称，简洁精确（如"梯度下降"而非"梯度下降法优化策略"）
- 英文缩写保留原样：CNN、LSTM、Adam、SGD、BERT、GPT
- 不加"的概念"、"方法概述"、"基础知识"等后缀
- 不写题目式描述（如"举例说明XXX"）

### 3.2 entity_type（课程批次只能使用以下 8 种）

| 类型 | 说明 | 每门课大约占比 | 示例 |
|------|------|-------------|------|
| `topic` | 大的主题分类、章节级 | 5-15 个 | 监督学习、卷积神经网络、概率分布 |
| `concept` | 基本概念、定义、原理 | 最多 | 过拟合、特征值、条件概率、梯度消失 |
| `method` | 方法、技术、流程 | 较多 | 交叉验证、反向传播、数据增强 |
| `algorithm` | 具体可实现的算法 | 较多 | 随机森林、Adam、K-Means |
| `application` | 实际应用场景/任务 | 5-15 个 | 图像分类、机器翻译、推荐系统 |
| `model` | 具名模型、模型族或可作为学习对象的模型体系 | 按需 | BERT、GPT、DeepSeek-V3、扩散模型 |
| `tool` | 工程工具、数据库、推理服务或实验工具 | 按需 | vLLM、TensorRT、向量数据库、Weights & Biases |
| `framework` | 开发框架、系统框架或方法论框架 | 按需 | PyTorch、LangChain、MLOps、RAG 框架 |

`exercise` 只用于练习/题目型节点或非课程批次，不要写入课程知识点批次。

### 3.3 description

- 一句话，20-50 字，说清"是什么/做什么"
- 好："通过计算损失函数对各层参数的偏导数来更新网络权重的训练方法。"
- 不好："一种用于神经网络的重要方法。"

### 3.4 关系类型（只能是以下 6 种）

| 关系 | 含义 | 方向 | 示例 |
|------|------|------|------|
| `SUBTOPIC_OF` | A 是 B 的子主题 | A → B | 决策树 SUBTOPIC_OF 监督学习 |
| `PREREQUISITE_OF` | 先学 A 再学 B | A → B | 矩阵乘法 PREREQUISITE_OF 线性变换 |
| `RELATED_TO` | A 和 B 相关联 | A ↔ B | 精确率 RELATED_TO 召回率 |
| `PART_OF` | A 是 B 的组成部分 | A → B | 卷积层 PART_OF CNN |
| `USES` | A 使用了 B | A → B | 随机森林 USES 决策树 |
| `APPLIES_TO` | A 应用于 B | A → B | CNN APPLIES_TO 图像分类 |

### 3.5 关系质量要求

- 用 SUBTOPIC_OF 构建 topic → concept/method → algorithm/application 层级
- **PREREQUISITE_OF 方向不要搞反**：A PREREQUISITE_OF B = 先学 A 再学 B
- 每个节点至少一条关系，不要孤立节点
- 关系数 ≈ 节点数 × 1.2~1.8
- 鼓励写跨课程关系（见第五节）
